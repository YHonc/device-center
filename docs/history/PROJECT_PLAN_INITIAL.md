# 桌面设备中心：开发规划

更新：2026-10-23。定位：Windows 本地轻量常驻设备中心。本文是实施规划，不代表设备接入已完成。

## 1. 已确认需求与边界

- 鼠标：ATK F1，具体子型号、接收器版本和固件待确认。
- 键盘：迈从 KX75。
- 挂灯：小米显示器挂灯 1S。
- 优先复用、参考 GitHub 项目；统一状态、控制入口和液态玻璃视觉。
- 暂按鼠标键盘使用 2.4G 接收器设计，这是待确认假设；有线/蓝牙必须作为独立兼容性组合验证。
- 首版：鼠标键盘电量与充电状态（仅在协议支持时）、连接状态、低电量提醒、挂灯开关/亮度/色温、托盘入口、可选开机启动。
- DPI、回报率、宏、改键、RGB、固件升级不进入首版。高级配置先通过默认浏览器打开官方驱动站。

## 3. 框架决策

建议 Tauri 2 + Rust + Svelte + TypeScript + Vite，Windows 首发。前端保持小型组件体系，玻璃样式用 CSS，不额外引入大型 UI 框架、实时折射着色器或 Electron。

| 候选 | 适配判断 |
|---|---|
| Tauri + Rust + Svelte | 首选：原生通信与 Web 界面分离，便于细致玻璃视觉；必须实测 WebView2 子进程总占用 |
| Rust + egui（沿用 QiLight） | 如常驻内存成为绝对优先项，保留为替代方案；复杂玻璃界面需更多定制 |
| Electron + Vue | 现有挂灯项目迁移最快，但不优先用于本次轻量化目标 |

上述是工程取舍，不是性能测试结论。初始化时核对官方文档、锁定依赖版本与许可证。Tauri 项目参考 tauri-apps/tauri；HID 库候选 ruabmbua/hidapi-rs；前端参考 sveltejs/svelte。无需为规划安装全局 skill。

## 4. 系统拆分

界面 → 受限 Tauri commands/events → DeviceService → 独立适配器 → USB HID / 局域网 UDP。

建议目录：

```text
src/                         Svelte 窗口、卡片、托盘面板
src-tauri/src/domain/        统一状态、能力与错误类型
src-tauri/src/adapters/atk/  F1 HID 适配
src-tauri/src/adapters/mchose/ KX75 HID 适配
src-tauri/src/adapters/miio/ 1S 控制
src-tauri/src/services/      调度、通知、配置、生命周期
tests/fixtures/             脱敏报文与解析预期
docs/evidence/              实机验证、性能报告、协议证据
references/                 上游参考快照，不作为应用依赖打包
```

统一 DeviceSnapshot：id、model、transport、connection、batteryPercent 可空、charging 可空、lastSeen、sampledAt、stale、capabilities、error。未知电量显示“未知”，历史值显示时间和过期标记；不能把未响应当作 0%。

适配器接口：discover、readSnapshot、executeTypedCommand、disconnect。前端不接触原始 HID 报文、token 或任意网络地址执行接口。每台设备独立队列，超时与错误不影响其他设备。

设备匹配必须结合 VID/PID、usage page、usage、接口与报告长度，不能只匹配品牌或产品名。未知型号只枚举，不套用其他型号命令。只读查询也可能需要发送 HID 请求报文；必须先确认命令语义。

## 5. 接入顺序与技术关口

1. 只读枚举本机 HID/PnP：记录 F1、KX75 的接口与连接方式；不全量抓取键盘输入。
2. F1：对照 atk-tool-plus 注册表和报文实现，确认准确子型号后建立 Rust 解析器与脱敏样本，再进行电量查询。
3. KX75：优先继续检索准确型号的 GitHub 实现；缺失时定位迈从官方脚本的设备注册、电量命令、响应解析。K99 仅作结构参考，不对 KX75 试发其命令。
4. 1S：先支持用户提供 IP/token，通过受保护本地存储保存 token；登录米家获取 token 后置，避免首版引入账号登录链路。
5. 实机电量与官方页面在接近时间比较，考虑缓存和取整；休眠、断开、充电、有线切换分别验证。
6. 协议验证通过后才接入正式界面；协议未完成的卡片明确显示“待适配”。

## 6. 液态玻璃 UI 规划

采用苹果液态玻璃的视觉方向，在 Windows 上实现相应风格；不宣称调用 Apple 原生材质。

- 主窗建议 980×680，可缩放：顶部标题与全局连接状态；中部鼠标、键盘、挂灯三张设备卡；底部场景与设置入口。
- 鼠标/键盘卡突出电量数字、细环、充电状态与最后更新时间；不显示虚构实时电量。
- 挂灯卡提供主开关、亮度/色温滑条、读写状态；拖动先更新预览，节流提交，释放后补发最终值；收到确认后才显示成功。
- 托盘弹窗约 360×440：两项电量、挂灯开关和两个滑条，不加载完整设置页面。
- 背景使用静态柔和渐变；主要浮层使用半透明底、细亮边、局部模糊与低强度阴影，正文区域保持稳定对比度。
- 圆角建议卡片 24px、控件 12px；正文 14–16px，关键读数 32px。浅色/深色独立调色，字体使用系统字体。
- 动画只覆盖交互反馈，约 140–220ms；不循环漂浮，不在后台持续动画。支持减少动态效果、减少透明度和纯色性能模式。
- 键盘导航、焦点可见、屏幕阅读标签、状态不只依赖颜色；100%/150%/200% 缩放验证。
- 普通 CSS backdrop-filter 不等于桌面背景透明；如要透出桌面，另行验证 Windows 合成材质与 Tauri 窗口兼容性，失败回退为窗口内部玻璃。

## 7. 轻量化策略与预算

以下是待实测目标，超标先定位再调整，不能提前作为交付成绩：

| 场景 | 初始预算 |
|---|---|
| 托盘稳定常驻 | 全应用进程树 private working set ≤80MB，平均 CPU <0.5% |
| 主窗静止 | 全进程树 private working set ≤180MB，平均 CPU <1% |
| 首次打开主窗 | 目标 ≤2秒，报告硬件与冷/热启动差别 |

前台电量默认每 30 秒查询、后台 120 秒，依据设备响应调整；优先利用可确认的状态事件。睡眠/离线指数退避，重新连接刷新。灯光滑条提交限制约每 100ms 一次并合并排队值。禁止高频全设备扫描。

关闭主窗后尝试销毁 WebView、仅保留 Rust 托盘与设备服务；销毁是否真正释放进程需要测量。显示弹窗再创建视图。稳定配置采用小型 JSON 与原子写入，不引入数据库或本地 HTTP 服务。

性能测量记录操作系统、CPU、内存、WebView2 版本、构建模式、设备数、采样方法；每种状态稳定后采样至少 10 分钟，报告均值、峰值和进程树明细。首次运行、冷启动与稳定态分开。

## 8. 可靠性与隐私

- token 存入 Windows 受保护凭据存储或 DPAPI；日志与导出文件脱敏。
- 断连明确标记历史读数；重试有上限；恢复不重复弹出低电量提醒。
- 默认不启用开机启动，不自动登录云账号，不上传设备数据。
- 固件更新不进入适配器通用指令接口；官方驱动网站由外部浏览器打开。
- 复用 QiLight 前明确项目许可策略；参考仓库与最终发行源码分离，并维护 THIRD_PARTY_NOTICES。

## 11. 追加范围：本地键鼠设置与状态动画

追加日期：2026-10-23。用户新增本地键鼠设置和协议操作状态动画。本节扩展第1节中“高级配置仅打开官网”的原有首版边界；上述历史规划与完成快照保留，不能据此判断新增功能已经完成。

- 设置入口由能力驱动：只有准确型号、接收器/连接方式、固件与 HID 接口匹配，并存在可核验协议证据的能力，才能开放操作。其他项显示待适配或不可用及原因，不用品牌名或相似型号推定支持。
- 候选能力为 ATK 的 DPI、回报率，以及 KX75 的灯光、休眠设置。它们是待协议证实的候选，不是已承诺兼容或已完成能力。固件升级和宏不自动纳入本次扩展。
- 后端维护精确协议白名单：绑定设备身份、报告长度、读写命令语义、参数范围、响应校验和读回规则。前端仅调用带类型的能力接口，不开放原始 HID 报文或任意命令执行。
- 每次配置先读取当前值，明确显示采样时间和读取失败；用户编辑后展示当前值与拟变更值的预览。用户点击“应用”后才提交，随后重新读取设备值并核对。没有对应读回证据时不显示配置成功。
- 失败需区分读取失败、参数无效、设备拒绝、超时、读回不一致与连接中断；保留最后确认值并标记过期，不以编辑预览覆盖已确认状态。重试和重新读取必须明确可控。
- 动画表达读取、待应用、应用中、读回验证、成功与失败等真实状态；与协议调用结果同步，不用固定播放结束代替成功确认。遵循减少动态效果设置，提供静态文字/图标等效反馈，不仅依赖颜色；后台不持续动画。

新增验收：准确设备身份与白名单证据、读取现值、预览不写入、点击应用才写入、参数边界、失败保留确认值、读回一致/不一致、断连恢复、键盘可操作与减少动态效果。当前均应按开发中记录，具体完成证据见 `docs/ACCEPTANCE.md` 的追加矩阵。

## 12. 追加范围：应用内米家登录配对

追加日期：2026-10-23。用户新增应用内米家登录取得挂灯token，扩展第5节“云登录后置”的原有范围。流程由用户发起，完成账号登录与云端要求的验证后，选择自己的设备；选中设备IP/token直接交给本地后端以DPAPI保存，不回显token。手动IP/token输入保留为备用。

实现分工为原生 `cloud.rs` 与前端登录/验证/设备选择界面协作。当前尚未实际登录验证，不能宣布账号链路可用。网页逆向仅可作为独立实现流程的备用依据，不能免除验证码、二次验证或其他云端验证，也不分发官网下载JavaScript。登录错误、验证未完成、过期会话、设备列表为空、地区不匹配及本地保存失败必须明确区分；未经用户发起不自动登录。

最新协议核验补记：ATK官网查询采用普通HID Output路径，此前Feature Report表述有误。已有一次FF02实机读取记录：电量95%、1000Hz、已有DPI第2档（共4档）；这只证明对应本机/时刻的读取，不证明所有F1或写入兼容。KX75 FF02型号probe已识别，电量与性能GET仍待后端确认。最终证据由 `docs/ACCEPTANCE.md` 汇总。
