# 后台电量监控

`src-tauri/src/monitor.rs` 在 Tauri setup 中启动一次 Rust 工作线程，不依赖主窗或 WebView 定时器。主窗可见时正常查询间隔为 30 秒，隐藏或销毁后为 120 秒；重新打开主窗立即刷新健康设备。仅通过 `battery_match` 匹配已批准的 ATK 373B:101A FF02 与 KX75 3554:FA09 FF02，调用后端受限的 `query_battery_sync`，不读取键鼠输入或发送配置指令。

枚举和各设备查询分别指数退避，失败后下一间隔为正常间隔的 2 倍，最高 900 秒，成功后恢复正常间隔。枚举失败不等同于断开；已确认的设备消失时发送断开事件，重连立即查询。线程在应用退出时由进程回收，不因关闭主窗而停止。

`battery-update` 成功事件使用原电量对象并附加 `deviceId`、`stale:false`、`connection:"connected"`。失败事件包含 `deviceId`、`error`、`stale:true`、`connection:"unknown"`；确认拔除时 connection 为 `disconnected`。deviceId 与 `list_hid_devices.id` 一致，使用设备路径的十六进制编码。前端应保留历史读数并明确标记过期，不把缺字段当作 0%。

低电量阈值为 20%。仅有有效且不超过 5 分钟的电量样本才能触发系统通知；未来时间、缺失电量、范围错误和过期样本均不触发。充电状态未知时，仍可基于有效电量提醒，不显示已确认充电。每设备每个低电量阶段最多尝试一次通知；充电明确为 true 或电量恢复到至少 25% 后开启下一阶段。21–24% 的波动、查询错误、拔插、休眠不会重置阶段。去重仅在进程生命周期内保留；重启后可再次提醒。通知失败也不在当前阶段重复尝试，因此不能把调用成功等同于用户看到系统提示。

验证范围：单元测试只覆盖间隔、退避、阈值、充电/恢复重置、错误期间去重及未知/过期/未来样本，不执行 HID I/O。设备休眠、拔插、主窗关闭后的实际轮询、Windows 通知展示以及系统睡眠恢复仍需实机验收。
