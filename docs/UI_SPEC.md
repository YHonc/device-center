# 新版视觉与交互规范

更新：2026-10-25。当前采用统一的窗口内部玻璃材质、紧凑设备摘要和分层设置界面。本轮补齐设备编辑的键盘操作、未知参数展示、搜索反馈和草稿关闭焦点；实现状态与待验项见 ACCEPTANCE.md。

## 窗口与信息结构

- 默认主窗目标1040×720逻辑像素，兼顾约610px高窗口；快捷窗320×320，采用自绘顶栏、无系统标题栏。
- 主窗顶栏44px、主体边距16–24px、卡间距12–16px。快捷窗顶栏40px，设备摘要每行44px。设备工作区宽度上限1120px并适应视口，连接使用聚焦模态。工作区内容内部滚动，键盘物理布局在自身容器横向滚动。
- 顶栏提供明确的拖动区域、应用名称、当前状态和最小化/最大化或还原/关闭控制；交互控件不划入拖动区。窗口拖动、双击标题区域、贴靠、缩放和系统快捷键必须在真实Windows桌面验证。
- 紧凑dashboard优先在默认尺寸完整呈现三台设备的关键状态与常用动作。顶栏后是简洁设备概览，鼠标、键盘、挂灯保持稳定视觉层级；不以大标题、大空白或装饰图挤出主要控制。
- 设备卡首先回答连接状态、当前读数、确认时间和可执行动作。设备图片/轮廓作辅助，不压过电量和参数，不生成虚构实时数据。
- 设备卡头提供明确文字“设置”，单击进入独立设备工作区；按键、性能、DPI、宏和灯效按设备能力分类展示。标签切换保留预览。打开时焦点进入关闭按钮；关闭或切设备经过未应用/通信中保护，有草稿时焦点进入“继续编辑”，取消放弃后返回触发关闭的控件。
- 应用偏好使用独立页面，主设备页面暂时隐藏并保留草稿。设备诊断仍只从应用偏好进入，使用独立模态。
- 快捷窗底部“设备设置 → 打开主窗”只负责打开主窗，随后从对应设备卡进入设置；不声称已自动打开某设备编辑器。打开失败在快捷窗显示实际错误。
- 米家配对用分步骤弹窗：用户发起→二维码/登录入口→等待扫码和云端验证→自动匹配唯一目标或手选→本机保存→读取挂灯确认。只有真实后端状态才能推进；设备选择不回显token。

## 视觉基线

主窗、快捷窗与设备设置工作区共用同一套浅色/深色材质。设备与挂灯大幅装饰图已移除；设备卡突出名称、真实读数和设置入口。用窗口静态渐变、半透明阅读面、顶部高光和克制投影表达层级，只有浮层局部使用模糊。

- 使用系统字体，正文和操作标签保持可读；电量、亮度等主读数突出，单位和时间次级显示。
- 同一层级使用一致圆角、边框、阴影和间距。当前主窗设备卡/挂灯卡圆角16px，普通控件8–12px；快捷窗使用平面设备行，具体值服从紧凑布局和可读性。
- 当前主要辅助文字为12px、表单/操作为12–14px、工作区标题16px、页面标题24px、主要读数24–32px。成功、警告、失败与对应浅底分别使用`--success`、`--warning`、`--danger`及`*-soft`语义变量，明暗和减少透明度均提供对应值。
- 材质用静态渐变、有限透明度、细高光边与局部backdrop-filter表达；不引入常驻shader、持续折射或后台循环绘制。
- 不把CSS backdrop-filter当成桌面透底；当前Windows方案可采用窗口内部材质。减少透明度/纯色模式必须保持层级和文字对比，不依赖模糊才能理解内容。
- 状态文字与图标同时表达未知、离线、过期、读取中、待应用、验证中、成功和失败，不只依赖颜色。未知电量不显示0%。

### 全页收敛（2026-10-23）

保留现有配色、系统字体和玻璃层级。样式依次加载 `style.css`、`motion.css`、`refactor.css`、`polish.css`；本次静态收敛集中在最后一层，动效集中在 `motion.css`。

- 主读数使用等宽数字；采样和连接说明保持独立留白。窄主窗隐藏装饰设备轮廓，避免覆盖说明，主内容纵向滚动。
- 主窗宽度900px以上双列；窄窗无线设备纵向排列、照明在下。快捷窗使用两条设备摘要与平面灯控，移除大圆角卡片、厚阴影和重复说明。
- 统一按钮、滑条、切换与单选控件的键盘焦点。窗口按钮的焦点环向内绘制，避免边缘裁切。
- 浮层宽度不超出视口，偏好长内容内部滚动；托盘选项在380px以下单列。窄设备工作区的分类导航和键盘示意各自在局部容器滚动，外层不承载横向溢出。宏动作行随实际容器宽度重排，保留完整的类型、状态、按键、延迟和删除入口。
- 主次字号沿用11/12/13/14px及现有标题尺度，间距沿用8/12/16/24/32px。短状态无需强行扩展成正文宽度。

旧版浏览器截图和尺寸证据位于 `artifacts/ui-refinement-20261023/`，不代表后续重设计已经验收；当前边界见 ACCEPTANCE.md。

### 统一材质（2026-10-24）

`polish.css`最后一层统一管理材质，前面的样式层保留布局责任。主窗、320×320快捷窗、偏好页、连接/预设弹窗及设备设置工作区共用下列CSS变量，不另建一套硬编码配色：

| 变量 | 用途 |
|---|---|
| `--glass-canvas` | 窗口底色及静态渐变 |
| `--glass-panel` / `--surface` | 卡片和工作区的高覆盖阅读面 |
| `--glass-chrome` | 顶栏、侧栏与工作区导航 |
| `--glass-overlay` / `--overlay` | 浮层与底部操作栏的高覆盖表面 |
| `--glass-edge` / `--line`、`--glass-highlight` | 外轮廓与顶部亮边 |
| `--glass-tint` | 静态细高光渐变 |
| `--glass-shadow`、`--glass-overlay-shadow` | 卡片与浮层的完整阴影配方 |
| `--glass-blur` | 浮层局部模糊，默认16px |

`--ink`、`--muted`、`--accent`、`--control`、`--quiet-line`继续用于文字、控制和分组。阅读面浅色覆盖82%、深色覆盖84%；浮层覆盖95%/96%，遮罩不叠加模糊，避免内容和多个模糊层一起发灰。快捷窗沿用平面设备行，不给每行增加卡片或大投影。

减少透明度通过`.solid`切换整套变量：窗口底、阅读面、导航、浮层和控制均为实色，去掉高光渐变和模糊，保留边界与阴影层级。该材质是窗口内CSS效果，不表示Windows桌面透底。

## 交互与真实状态

挂灯主窗与快捷窗共用暖冷色带和灯光预设。色带只表示2700–6500K白光，不是RGB。内置“阅读”“专注”“柔和”是方便选用的数值，不表示健康或照明标准。预设只应用亮度与色温，保持开关状态。

预设按钮点击后进入既有挂灯队列并等待真实读回，匹配态只根据已确认状态显示。卡片上直接提供保存当前灯光入口，自定义预设旁直接编辑名称和删除，无独立管理弹窗。名称trim后1–32字符；Enter保存，Escape取消并恢复焦点。删除后若原触发控件消失，焦点回到可用的保存入口或预设组。名称编辑期间不能保存当前灯光。保存保留设备实际整数色温，如4809K；未知、过期、通信中、100ms防抖尚有待发值和窗口关闭期间不能应用或保存当前读数。重命名/删除只修改本地目录，可离线执行。

自定义预设按 `lamp-preset-v1:<uuid>` 分键保存，内容为 `{version:1,preset:{id,name,brightness,temperature}}`，无Token、电源或采样时间。两窗通过storage事件及桌面无内容变更通知刷新目录；通知不会触发设备写入。损坏条目不加载、不覆盖，其他合法预设仍可使用。

设备配置遵循读取现值→用户编辑→预览差异→点击应用→读回核对。ATK提供回报率、已有DPI档位、参数、设备宏及分类按键映射；KX75提供基础性能、分层改键和内置灯效。能力及可编辑字段由读取结果声明，其他能力显示具体原因。完整块CAS失败时要求重新读取和预览，不自动覆盖设备变化。

按键映射按功能分组搜索；ATK键盘按键、组合主键候选与KX75功能使用同一搜索反馈。非空搜索无结果时显示明确空态与清空搜索入口。未读取时显示等待读数，不把未适配分组当作读取失败。

DPI滑条按方向键移动到相邻合法值，Home / End到能力声明的首末值，PageUp / PageDown移动十个合法步长。数字输入保留左右箭头、Home / End等文本编辑操作；只有上下箭头和翻页键调整数值。读取失败或应用失败后控件保持未确认状态；撤回预览不会恢复写入资格，须重新读取后再编辑。

宏录制仅采集输入区内的按键；Escape停止录制并保留工作区，Tab停止录制后按正常焦点顺序离开。两键不在录制时加入动作，可通过“添加动作”手动选择。停止、失焦或切换分类时补齐尚未释放的按键。宏动作写入和绑定分成两个区域，先确认槽内容，再绑定到按钮。

KX75切换灯效模式时，目标槽的亮度、速度和颜色尚未知，先隐藏旧模式参数并仅提交mode变更；应用并读回目标模式后才显示和开放其参数。未知参数显示“未知”或“尚未读取”并禁用，模式不适用的参数显示“不适用”。键盘示意只采用已读取且可用的单色数据，不用默认白色或旧模式颜色代替设备读数。

读取及应用期间提供明确进度和空态，禁止重复冲突提交；保持最后确认值与拟变更值的区别。写入后失败可能意味着设备部分生效，应提示撤回预览并重新读取核对，不把撤回或旧快照当作重新确认。挂灯滑条保持合并提交与最终值补发，设备读回前不显示最终成功。

扫码弹窗需要明确区分：二维码加载、可扫码、等待手机确认、需额外验证、二维码过期、网络失败、设备加载、无设备、保存失败和完成。显示实际失效时间或后端状态；没有证据时不伪造倒计时或自动成功。关闭/取消停止前端轮询并妥善结束会话，不保留可再次使用的敏感内容。

## 动画规范

- 动效服务于层级变化和操作反馈：抽屉滑入/退出、弹窗出现/关闭、标签切换、数值确认和状态图标变化。小交互以140–220ms为起点，复杂面板可适度调整，最终以真实桌面观感验收。
- 进入与退出可以采用不同的时长/曲线；不通过大幅缩放、弹跳或长距离运动掩饰等待。处理中可以保留低成本状态指示，不让所有设备卡持续动画。
- polish抽屉进入250ms、退出150ms，进入/退出位移16px/6px；真实体验不佳时调整并复核，减少动态效果时取消位移与缩放。
- 动画结束不触发协议写入或表示成功。网络等待时展示真实状态；成功反馈只能由读回确认驱动。
- 卡片不整体缩放或逐块飞入。快捷窗使用150ms纯淡入；展开使用180ms高度过渡，浮层使用可逆的进入/退出过渡。控制只过渡颜色和边缘反馈，不使用持续流光或循环动画。
- 尊重系统减少动态效果；在减少动态效果模式中使用即时状态切换或短淡入，移除大距离位移、弹跳和循环运动，保留等效文字与焦点反馈。窗口隐藏后停止无意义动画。

|---|---|
| 布局 | 默认1040×720完整呈现关键状态与操作；窗口缩放、100%/150%/200%系统缩放截图；无内容重叠、裁切或横向溢出 |
| 自绘窗口 | 无重复系统栏；拖动区不吞控件点击；最小化/还原/关闭、贴靠及快捷键真实桌面验证 |
| 抽屉/弹窗 | 键盘可打开关闭、Escape按预期处理、焦点进入并在关闭后返回触发控件；遮罩不允许误操作底层 |
| 扫码流程 | 正常链路及过期、额外验证、取消、无设备、保存失败逐项验证；静态页面和二维码图片不算登录成功 |

| 动效 | 可见状态与真实请求同步；快速打开关闭、重复操作、慢响应和错误下无卡死或错误成功反馈 |
| 资源 | 新版release全进程树独立测量；主窗静止、托盘常驻和扫码操作分场景记录，不用混合样本推导idle达标 |
