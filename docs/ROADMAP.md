# 开发规划

文档核对：2026-10-27。当前源码基线为10月24日设备功能扩展及10月25日全页UI与编辑交互收敛，包含合法DPI键盘步长、宏停止录制、模式参数读回前隐藏、搜索空态、草稿关闭焦点及预设离线编辑。10月25日记录为前端44/44测试、构建0错误/0警告，未改Rust或重打包；具体证据与待验项集中在 ACCEPTANCE.md。

| 顺序 | 工作 | 完成条件 |
|---|---|---|
| 1 | 协议与能力边界 | 核对任意DPI、组合键、宏、灯效和固件的官方来源；区分可编码能力、缺失协议与只读入口 |
| 2 | 完整实现与界面接线 | 已有协议的能力贯通前端、命令和后端；设置保留原块并完整读回；宏本地编辑与设备执行分开说明 |
| 3 | 离线验证 | 前端行为测试与构建、Rust mock测试通过；验证越界输入、预览过期、非目标字节保留与读回失败；不连接硬件或云服务 |
| 4 | 交付准备 | 同步当前文档；需要构建时记录版本、文件哈希、对应源码和验证范围；旧发行包保持其原验收范围 |
| 5 | 最后：功能与系统实测 | 按设备读取原值→单项应用→完整读回→实际行为核对；再验收断连、休眠、窗口/托盘、灯光、通知、自启与性能；固件升级另行确认精确型号与升级契约 |

已有能力与实现状态见[当前验收矩阵](ACCEPTANCE.md)，接口与参数边界见[设置契约](SETTINGS.md)。

当前优先项是将已完成的源码变更纳入下一次明确的交付，再按验收矩阵进行功能与系统实测。上表是完整开发顺序，已有实现与离线证据可直接复用，不重复从协议调研开始。实测按后续任务授权执行。

扩展范围：DPI数值、组合键、宏编辑和灯效已按能力边界实现部分功能，缺口见 SETTINGS.md。原生固件升级尚无完整契约，当前产品已移除固件入口；后续重新纳入时确认二进制、分包、校验与恢复流程。

每项完成后更新 ACCEPTANCE；不把历史测试结果转记为新版本实测。
